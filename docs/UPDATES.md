# 更新检测与原地升级

设置页的“插件更新”只显示版本、检查与升级入口；独立升级页提供更新说明、下载或已授权的原地升级。首次从旧版安装升级器仍需手动下载、覆盖原目录并重新加载。

## 使用方式

自动检查默认开启，可在设置页关闭。浏览器启动、安装/更新及每天一次的 alarm 会检查；同一天通常复用结果。手动检查至少间隔一分钟，网络失败不无限重试。发现正式新版时图标显示 ↑，用户再决定是否更新。GitHub 暂不可达时显示失败及上次观察，不把失败当成最新版本。

已授权用户在升级页点击“立即升级”，程序先请求必要的写入许可，再自动下载、校验、备份、安装和重新加载。未授权用户的主操作是“前往下载新版”，不强制要求绑定目录。首次授权与恢复备份放在折叠的可选设置中。正常安装不会清除 API Key、设置或用量；不用卸载。目录句柄保存在本机 IndexedDB，浏览器可能再次要求授权。成功后刷新已有 B站视频页；未保存的设置应先保存。

需要定位目录时，升级页提供“打开当前插件管理页”，直达 `chrome://extensions/?id=当前扩展ID`，在 Chrome 的“来源 / 从以下位置加载”查看原路径。普通扩展 API 不提供这个本机路径，不使用 Chrome 私有 API 或调试权限模拟普通用户能力。原安装目录必须是 Chrome 实际加载的目录，直接包含 manifest.json。程序写入一个临时随机探针并通过当前扩展地址读回，以区别真正目录与同名副本，随后删除探针。目录失效、拒绝授权、API 不支持或新版需要新增权限时，使用下载升级。

## 实现边界

- 仅查询 `chenyanshan/bilibili-ad-skipper` 的 GitHub 正式 Release，拒绝草稿、预发布和缺附件的版本。请求不附浏览器凭据、Key 或观看数据。
- 下载固定仓库的 ZIP 与 SHA256SUMS；核验字节数、SHA256、每个 ZIP 文件 CRC、路径、文件数、解压大小，以及 manifest 的名称、版本、权限和必需入口。不执行下载内容来做校验。
- 多设置页写入用 Web Locks 排他；在独立 IndexedDB 保存被覆盖文件的旧字节，再逐文件写入并读回校验，manifest 最后写。没有覆盖的文件保持。常规写入异常尝试回退；提供恢复上次备份按钮。
- 更新不是跨文件原子操作。关闭页面、浏览器崩溃、权限变化或磁盘问题可能中断写入并阻止自动回退。如果设置页也无法打开，下载 ZIP 覆盖原目录，在 Chrome 扩展管理页重新加载即可恢复源码；不要卸载，否则可能丢失本机配置。
- 当前是 Chrome“加载已解压扩展”，开发者模式需保持开启；原地写入须用户选择目录并授权，不等于 Chrome 商店后台静默升级。商店分发及签名 CRX/企业部署未实现。

相关官方接口说明：[runtime.reload](https://developer.chrome.com/docs/extensions/reference/api/runtime#method-reload)、[File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)、[扩展分发方式](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)。

## 验证范围（2026-10-01）

135 项 Node 测试通过，覆盖版本数字排序、固定来源、发布附件完整性、每日/手动冷却、并发、关闭检查、网络失败保留旧观察、损坏包/路径穿越/重复文件、新增权限、备份失败、写入失败回退和旧文件恢复。

隔离 Chrome 使用真实页面与生产模块验证：

- 从当前扩展 URL 读回临时安装目录中新建的探针文件。
- 使用浏览器真实 OPFS 文件句柄测试写入、恢复、IndexedDB 中备份与句柄持久保存；这里的探针网络由测试替代，**不是实际安装目录授权测试**。
- 仅在临时安装目录把测试版本 0.7.0 改为 0.7.1，再调用真实 runtime.reload，读回新版本且存储哨兵、备份、句柄保持。两者都是隔离测试，不是发布 0.7.1。
- 模拟未来 0.8.0 附件，在 Chrome 中通过生产下载/ZIP/SHA256/manifest 校验；选错目录被拒绝、取消原生选择没有执行升级。
- 设置页在 1180、760、390 像素宽度截图查看，无横向溢出。

**原生目录选择仅验证了取消；从人工选择真实安装目录、授予写权限到整包覆盖的完整端到端流程尚未验收。** 不能把 OPFS 和测试脚本替换磁盘文件写成真实用户一键升级成功。验证摘要见 `research/update-validation-2026-10-01.json`；本轮未更改用户实际安装的扩展。
