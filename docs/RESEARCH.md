# 实现调研（2026-09-27）

## 字幕路线

已在用户授权的登录态 Chrome 中实际调用：

1. `https://api.bilibili.com/x/web-interface/view?bvid=BV1A5aP6wETR`
2. `https://api.bilibili.com/x/player/wbi/v2?bvid=BV1A5aP6wETR&cid=42157214438`
3. 上一步 `subtitle.subtitles[0].subtitle_url` 指向的 HTTPS `aisubtitle.hdslb.com` 地址。

播放器响应 code=0，返回 ai-zh，ai_status=2；下载得到 139 条字幕。没有手动点击打开 AI 字幕。签名后的字幕 CDN URL 会过期，不应该作为永久缓存；插件缓存广告结果而不是该 URL。

测试视频：[盘点那些只有开挂才能发现的游戏彩蛋](https://www.bilibili.com/video/BV1A5aP6wETR/)。真实接口请求完成，识别结果为空。该样本证明链路可用，不证明识别准确率。

尚未实证：未登录是否可获取、生成字幕是否一定要打开开关、其他账号/地区的字幕可见性。不能把单次成功推及全部视频。当前采用接口优先、缺失时人工开启重试的策略。

## 开源方案

GitHub 仓库搜索确认：[hanydd/BilibiliSponsorBlock](https://github.com/hanydd/BilibiliSponsorBlock)，描述为从 SponsorBlock 移植的 B 站恰饭片段跳过插件，属于社区提交广告时间段路线。适合热门内容且不产生模型费，但覆盖依赖提交者。

后续 GitHub API 遇到共享出口限流、源码页面请求超时，因此没有声称审阅其实现，也未复制其源码。本项目独立实现，不对接未知的公共标注服务器。若未来接入，应先核实服务接口、使用条款和数据许可。

## 方案取舍

- 已生成字幕 + LLM：第一版采用；无需音频下载、服务器、ASR，支持用户自备 Key。
- 社区广告时间段：可作为后续优先命中/降成本层，第一版没有接入。
- 音频转录：可补齐无字幕视频，但增加媒体下载、转录成本、权限、等待时间，第一版不采用。

当前提示词和边界限制偏保守，目标是优先避免把正常游戏介绍当成植入。模型存在漏报、误报，撤销和手动保留始终可用。

## 2026-09-28：以真实字幕修正省 Token 策略

采集 19 支真实视频的字幕，覆盖游戏解说、旅行、影视、科普和数码；不能把“采到 19 支”当作“19 支完整人工标注”。完整字幕只在本机 research/private-corpus.json，已忽略，不放入发布包。针对候选段做了人工阅读和 7 支视频的真实 API 尝试，其中 6 支完成，第 7 支遇到 HTTP 429；未拿失败响应当成无广告。

另实际读取 BilibiliSponsorBlock README（通过 jsDelivr 镜像）及其公开 `/api/skipSegments?videoID=…&categories=["sponsor"]`。该接口存在多个 CID 的标注且票数可能为 0；它是弱参考，不是金标准。当前插件不向该服务发送浏览历史，也未接入它自动跳过。先用它定位研究样本，再阅读相应字幕。

### 省 Token 的实际口径

先在本地完整扫描字幕，再发送候选。下表是字幕载荷字符数，不是 tokenizer 实测 Token，也不含提示词、标题、最多 700 字赞助上下文和可能的扩窗重试：

| 样本 | 完整字幕字符 | 候选字幕字符 | 字幕字符减少 |
|---|---:|---:|---:|
| 山西 | 10,243 | 3,409 | 约 67% |
| 恐怖片 | 3,919 | 1,225 | 约 69% |
| 诡异广告游戏 | 48,979 | 5,337 | 约 89% |

初次真实调用服务商报告：恐怖片 prompt_tokens=900、completion_tokens=223；诡异广告两次合计 prompt_tokens=3266、completion_tokens=76。后续补充赞助上下文和修改提示词会改变实际 Token，因此不能承诺相同数字或按字符减少直接计算账单降幅。没有实测全文调用的同条件账单对照。

### 当前实现边界

- 不超过 8 分钟直接读全文：3–5 分钟里插 1–2 分钟广告，优先避免漏掉它，而不是过度节省少量输入。
- 长视频才做本地宽召回，合并重叠窗口，保留前 60 秒、后 120 秒。短句跨行拼接。强线索、不同商业线索组合、产品指代加连续功效描述均可召回。
- 带少量全视频的赞助上下文，避免将同一赞助产品的第二次出场错当普通介绍。
- 每次传 `[字幕ID,文本]`，不重复传 from/to；时间由本机映射。每块最多约 6000 个字幕 JSON 字符/240 条，必要时重叠 12 条；单视频最多 24 次请求。
- 若广告碰到候选窗口边界，预算允许时向两边各扩 60 秒重试一次。仍不完整的片段保留播放。
- 默认只自动跳过 ≥20 秒且模型自评 ≥0.9 的片段；数秒提及不折腾。去掉原 65% 比例限制，允许短视频里较长的广告，仍拒绝近乎整片（≥95%）和超过 4 分钟的片段。
- 无明显候选不调用 AI，但这不证明无广告。新品牌、无文字软植入、ASR 错误仍可能漏掉；设置可关闭省 Token，改用全文。
- 本轮规则有针对已见样本的修正，不能把同一批样本上的结果当作独立测试集准确率。尚未取得并人工确认用户所述“3 分钟内 2 分钟广告”的真实样本，当前仅为该结构做了边界回归测试。

补充复测结果：加入全片赞助上下文后，山西中段模型从“无广告”改为 715.05–724.37 秒，只确认约 9 秒产品卖点，仍没有覆盖社区约 34 秒标注。按照当前用户偏好，这 9 秒不自动跳过。这里是边界/覆盖尚不充分的真实限制，未继续反复调整提示词把单个样本“调到过关”。

### 用户确认的覆盖优先偏好

随后用户明确接受少量误跳，重点拦转转、妙界这类较长广告。最终门槛调整为模型自评 ≥0.8、时长 ≥20 秒，提示词改为对明显倾向商业推广的模糊段落给出候选，不再一律弃权；此前 0.9 的对照记录属于修改前实验。

补充查询 3 支视频，其中 2 支取得字幕，1 支没有字幕：

- [妙界广告合集](https://www.bilibili.com/video/BV1Urj8z9ETJ/)：实际出现“推荐下妙界肩颈按摩仪”、肩颈揉捏、力度与使用体验等连续卖点，确认用户所说“秒界”可能对应妙界，二者均作为召回名称。合集不是普通视频的独立广告标注，不用它评估跳过准确率。
- [八千买5090显卡](https://www.bilibili.com/video/BV1VD8V6rEd5/)：实际讨论转转回收价格和质检问题，并明确表达批评。说明即便用户允许误跳，品牌名仍不应直接等于广告。
- [B站四大广告商](https://www.bilibili.com/video/BV19XdiYBE8Y/)：无可用字幕，没有编造内容。

累计尝试 22 支、取得 21 支字幕。最终省 Token、自动播放流程在真实恐怖片视频中再次验证：进入页面自动识别，约 528–552.64 秒判为广告；测试播放至 529 秒实际自动跳到 552.64 秒，撤销恢复至 529 秒。随后用户要求覆盖优先，修改门槛和提示词并通过 14 项回归；未对新提示词重做全部真实 API 样本评测。
