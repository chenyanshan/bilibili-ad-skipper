# JEV / LLM 双识别方式

## 来源和接口

按用户提供的 14 页 PDF，以及实际查阅的官方 [API reference](https://docs.typesafe.ai/api) 实现：

- JEV：`POST https://api.typesafe.ai/v1/systemone`，`Authorization: Bearer <apikey_…>`，模型默认 `jev-latest`。
- `state` 为待判断内容；`questions` 为命名问题。`noul` 返回 0–1 概率，`choice` 返回选项及分布/置信度。JEV 不生成解释、字幕或任意起止时间。
- 官方明确指出问题 map 的 key 不参与推理，因此问题正文和选项描述都明确指出待判断字幕 ID。
- 单道 choice 最多 255 个选项。本实现每块最多 240 条字幕，加 `none` / `outside` 为 242 项。
- 按所附文档建议：中文字幕不翻译，判断问题用英文。中文识别效果仍需实测。

## 社区优先

插件先查询 BilibiliSponsorBlock 社区的 sponsor 广告；已有广告就采用社区结果，不调用 AI。社区不需要 Key，社区区间不受 AI 最短 20 秒规则影响。以下字幕流程只在没有社区广告时运行。

JEV 本地跳过阈值与社区自动投稿阈值分开：自动投稿默认关闭，另行开启后仍要求广告概率、起止 confidence 和所选边界 probabilities 均 ≥0.90，边界完整且实际自动跳过才尝试。LLM 只能手动投稿；失败不自动重复投稿，无广告结果只保留在本机 7 天。

## 无字幕时的自动尝试

社区未命中且需要调用 AI 时，先正常读取字幕；首次返回空列表才尝试使用播放器现有的中文 AI 字幕入口。控件最多等待约 2 秒，随后最多 4 次读取，总等待预算约 8 秒。取到字幕、失败或取消后恢复自己临时打开的开关，已有字幕不触发操作，用户本来已开的字幕保持开启。用户操作字幕或切换视频后，不继续覆盖其选择或点击新播放器。没有已知入口或播放器要求登录时不点击，不强制生成字幕，也不把获取失败当作无广告。此能力同时适用于 JEV 和 LLM。

## 当前 JEV 流程

1. 社区无广告时，JEV 分块检查完整字幕，不再用本地关键词决定是否发送。原有省 Token 设置保留，仅用于 LLM。
2. 每块最多 160 条、约 4000 个字幕 JSON 字符，重叠 12 条；先询问是否含任何一段商业推广。临界概率（≥0.45 但低于用户门槛）仅触发更小窗口复核，不能据此跳过。
3. 达到用户广告概率门槛后，选择首段广告的起止字幕。无广告块无需构造边界选项。继续检查已识别段之后的字幕，避免漏掉同块多广告。
4. 两个边界矛盾时，允许基于已选中的另一端做一次有条件的重试；仍矛盾则缩小窗口复核，不制造起止时间。局部未确认不抹掉其他已确认的广告。
5. 碰到块边缘时在候选广告前后各加入 60 秒；边界置信度低于 0.5 时前后各加入 20 秒，复核起止。若扩大后超过 240 条/约 6000 字符，截断广告保留播放。复核结果必须与原候选相交。
6. 重叠结果合并后，超过 240 秒的广告额外逐块确认整个范围是连续推广，每块概率须 ≥0.90 且达到用户门槛；失败保留播放。近乎整片（≥95%）仍拒绝自动跳过。
7. 全流程单视频最多 24 次请求，包含存在判断、边界、后缀检查和复核。预算用尽或边界不完整，显示未检查完，只保留独立确认的片段，不缓存成无广告。服务失败不回退到 LLM。

默认最短自动跳过时长仍为 20 秒；JEV 广告概率门槛仍为 0.65，LLM 自评分门槛仍为 0.8。用户已有 Key、URL、模型、服务选择、阈值和开关不被覆盖。升级后的算法缓存隔离，避免复用旧版漏检结果。

修复或复核过边界、超长复核广告不获得自动投稿资格；用户仍可明确手动投稿。模型广告概率、边界评分和人工准确率是不同概念。

真实对照、用量与限制见 [2026-10-01 评测](JEV-EVALUATION-2026-10-01.md)。

## 为什么不用直接问“从几秒到几秒”

JEV 没有自由文本输出。把起止位置变成受限 choice 才符合接口；程序仍需处理无广告、多广告、边界超窗和不一致答案。最初试验把有无广告和两个边界一起问，对无广告视频也产生了大量无用的 choice 输入；最终改为先门控，再并行问边界，避免这部分浪费。

循环无法在 API 内依赖同一请求其他题目的结果，所以“下一段”由程序串行推进。一次只找第一段，避免开始来自广告 A、结束来自广告 B。

## 配置和数据隔离

设置页默认 JEV 在前且为新安装首选，LLM 在后且默认地址和模型留空。通过识别方式切换 JEV / LLM。两者各存自己的 URL、模型、Key、阈值。旧版 LLM 配置自动保留，未选择 JEV 时不使用 JEV Key。用户本机配置可切到 JEV，但分发包没有任何 Key。

缓存按服务、模型、地址、阈值、视频 CID、算法版本和候选设置隔离；切换设置会清空当前播放页的旧结果并重新读取/识别，旧服务不会再发起后续请求。已经发送到服务器的请求无法撤销。概率数据和 `usage.input_tokens/output_tokens` 留在结果统计中，不能把字幕字符数直接当成账单 Token。

JEV 地址同样可配置，支持根 URL、`/v1` 和完整 `/v1/systemone`；仅 HTTPS 或本机 HTTP。默认 TypeSafe 域名已声明权限，自定义服务按域名申请权限。

历史社区集成验证使用模拟公开接口和测试占位配置，未使用真实 Key，也未向线上社区投稿。下方历史实测保留当时记录，不代表本次重新测试。

## 历史验证和局限（全文门控更新前）

- Key 的真实 ping 返回 HTTP 200 和 `answers.ok.noul`。
- 第一版三题并行实测：恐怖片洗发产品 528.05–552.64 秒；正常游戏彩蛋和批评转转的视频无广告；耐克样本只选出 53.28–57.68 秒末尾引导语，漏掉前段推广，按 20 秒门槛不会跳过。这是模型边界能力的实际限制。
- 最终门控版本的实测记录在本机 `research/private-jev-results.json`；对照记录在 `research/private-jev-baseline.json`。完整字幕、Key、原始研究记录不打入发布包。
- 不声称 JEV 与 LLM 准确率相同，不声称 JEV 一定更少 Token。choice 含多个选项和概率分布，其输入通常多于简单的一次 LLM 提示；是否更省钱取决于实际 usage 与服务商价格。
- HTTP 401/422/429/529 或超时会明确报错，不把失败当“无广告”，也不自动换服务产生另一份账单。当前不自动重试网络错误；可通过“重新识别”重试，下一次正常打开也会重试。

### 最终版本实测（同一批真实字幕）

| 样本 | 结果 | API 请求次数 | 报告的输入 Token 总计 |
|---|---|---:|---:|
| 恐怖片中的洗发产品 | 528.05–552.64 秒，广告概率 0.92 | 3 | 8,822 |
| 老番茄毕业知识抽查中的耐克推广 | 36.36–57.68 秒，广告概率 0.84 | 4 | 14,740 |
| 游戏彩蛋解说 | 无广告，概率 0.04 | 1 | 3,341 |
| 批评转转回收的视频 | 无广告，概率 0.11 | 1 | 1,702 |

耐克边界的选择置信度只有 0.29，尽管该次所选边界吻合人工阅读，也不能宣称稳定准确。初次三题并行无广告游戏样本消耗 13,259 输入 Token；门控后同一字幕样本为 3,341，约减少 75%。有广告样本因多一次门控可能稍增输入或延迟，不能宣称所有视频都节省同样比例。

真实 Chrome 验证：设置页选择 JEV 并保存，JEV Key 已配置、原 LLM Key 仍保留；新视频页自动调用 JEV（三次，后台记录 8,876 输入 Token），识别 528.05–552.64 秒并发生自动跳过，撤销按钮恢复播放位置。23 项核心回归测试通过。
