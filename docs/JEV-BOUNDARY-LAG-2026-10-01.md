# JEV 起点偏晚与播放器触发延迟（2026-10-01）

## 结论与验证范围

用户观察到“广告最开场几个字已经出来才自动跳过”，代码和实测支持至少两条独立原因：JEV 的识别起点偏晚，以及播放器只依赖 `timeupdate` 的触发等待。需要分别处理，不能用一个固定提前量掩盖所有边界错误。

分析阶段重新运行当时源码（v0.6.1），逐请求重放今天早些时候保存的真实 JEV API 响应：21 支社区广告视频和 5 支历史负样本，共 26 支。每次核对请求问题名、字幕 ID 列表、调用总数与最终区间，全部与原运行一致。社区区间仅参与事后比较，没有送入模型。当前源码与原评测有配置/用量相关改动；识别流程重放结果一致，不等于重新向 JEV 发出请求。

**本轮没有完成新的在线 JEV 推理。** 环境无 `JEV_API_KEY`，可连接的 Chrome 配置未找到本扩展；已请用户提供正在使用的浏览器名称和问题视频。没有打印或复制 Key，也没有修改用户浏览器设置。复核使用的原始 API 运行时间保存在逐视频结果中，不能把历史重放写成新的在线盲测。

此外，在前台 Chrome 用本地合成静音 MP4 做了 24 次播放器触发实验，独立比较 `timeupdate` 与逐帧检查；这不是 B站实播或音频输出延迟测量。

## 起点为什么偏晚

1. **模型常从品牌正文开始，而没有纳入直接相连的商业转场。** 爱回收样本在品牌名前已有“钱包可经不起这么烧”；薇姿样本先由角色头发转到“清爽无屑”；护肤样本从“皮肤出油也是一样”开始讲痛点，约 21 秒后才提套装。模型区间从后面的品牌句开始，不能靠提高播放器检查频率补回。
2. **字幕时间粒度限制。** JEV 只能选字幕 ID，程序取该行的 `from`/`to`。社区起点可能落在一行字幕中间，例如跑团样本的社区起点 205.933 位于 204.829–206.469 的字幕内，模型选下一行会天然晚 0.536 秒。仅靠整行 choice 无法证明亚秒口播边界。
3. **当前复核触发不足。** `jev-analysis.js` 只在碰到块边缘或边界置信度低于 0.5 时扩窗复核。高分边界也会偏晚：妙界样本边界置信度为 0.90，起点仍晚 3.453 秒。因此置信度不是时间误差上界。
4. **等待结果也可能漏掉开头，但本批没有证明它是主因。** `content.js` 收到结果后只渲染，不立即调用跳过检查，随后继续等 `timeupdate`。网络慢、进度被拖到广告附近、或广告发生很早时更明显。原 26 支 API 分析中位耗时约 1.95 秒、最大 6.35 秒；按从 0 秒连续 1 倍速播放的假设，没有一条模型起点早于对应结果完成时间。这里不包含字幕获取耗时或用户实际播放状态。

## 播放器触发实验

原 `content.js` 的自动检查仅挂在 `video.timeupdate` 上，条件为 `currentTime >= segment.start`，没有预测定时器或逐帧检查。其一秒定时器主要用于发现视频与设置，不是在每秒准点执行跳过。

本地 4 秒、30fps MP4，Chrome 前台、静音；每组 6 个不同起点，共 24 次。在实际媒体元素越过起点时记录 `currentTime`，再执行 seek。下表为**视频时间**的超出量，不是墙钟时间或扬声器延迟。逐帧检查也是越过原起点后才跳，没有预先裁剪内容。

| 检查方式 | 倍速 | 中位超出 | 最大超出 |
|---|---:|---:|---:|
| timeupdate | 1× | 68.94 ms | 148.64 ms |
| timeupdate | 2× | 454.15 ms | 754.21 ms |
| requestAnimationFrame | 1× | 10.15 ms | 21.24 ms |
| requestAnimationFrame | 2× | 112.78 ms | 126.26 ms |

样本少，实验未测 B站解码器、后台标签、CPU 忙碌、音频缓冲，也未给出统计置信区间。2 倍速结果不能直接折算成用户实际听到了多少字。它只证明当前事件驱动方式能够产生可察觉等待，逐帧方案在本实验中减少了这一部分等待。

## 建议的处理顺序

### 先修播放器时机

在已有明确区间的前提下：结果到达即检查；按离下一起点的距离和倍速安排定时器，临近起点用逐帧检查，保留 `timeupdate` 兜底。播放、暂停、倍速改变、拖动、切换视频、设置变化都重排或取消；撤销和保留片段照常生效。后台页面不能只依赖 rAF。保持模型/社区原始起点及投稿区间不变。

这能解决一部分“已经到点但还没执行”的延迟，不能解决数秒或数十秒的模型漏前导语。

### 再增加广告起点专项复核

对已确认广告，保留其主体与终点为锚点，检查起点前有限上下文（例如先 20–30 秒、必要时有界扩大）。专门询问同一商业推广的痛点铺垫、剧情转场和产品引入从哪条字幕开始，而不只找品牌名称。所有确认广告都可进入这一步，不只低于 0.5 置信度的边界。

复核不得看到社区答案；必须仍与原广告相连，不能越过明显正片或并入另一条广告。缺证据时保留原边界，扩展后的自动投稿资格关闭。新请求计入原 24 次预算；评测应同时报告新增费用、未完成率、起点误差与社区之外的覆盖，不能只追求提前。

应重新在线跑全部 21 支社区样本及 5 支负样本，并加入其他作者的新样本；对两端偏差、中位/P90、遗漏段数和社区外覆盖做前后对照。长广告、短广告、负票记录单列，不用开发样本指标冒充独立准确率。

### 亚秒补偿作为最后一步

若人工听原音确认字幕普遍晚于口播，再考虑可关闭的小幅本地提前量；不能直接统一提前 3–5 秒，更不能因此改写社区投稿边界。当前尚无音频级人工金标准，不应承诺固定提前量可以消除漏字。
